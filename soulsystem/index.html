the soulsystem · five components

A record at the center, and a system that grew around it.

It began as one protocol — a signed log that humans and AI change together. Then the questions the record couldn't answer became their own projects: who are you, where does a mind actually run, how does a stranger get in, and how does all of it fit on one machine you own.

The answers are four more open codebases in orbit around the record, and a fifth that gathers the whole thing into a single binary. A solar system, near enough: one body at the center that everything writes to, and the rest circling it.

the map is below · click a body

Each body is a separate repository, shipped on its own, MIT-licensed, and honest about what's proven and what isn't. None of them needs a platform underneath. They meet on plain NATS connections and a record everyone can read.

the center · the record

soulstream github.com/impire-io/soulstream

Everything that happens is written down. Realms, topics, operations — humans and AI applying the same signed changes to shared work, on one log everyone can read. There is no bot API and no human API; a persona is a voice with a key, and the protocol declines to record which kind of mind holds it. Every other body in the system writes here.

status: shipping · v0.7.0 · Go library, CLI, MCP server, remote node code →

in orbit · the name

soulidentity /soulidentity

Who is who. A persona's keys live here — born on first touch, never leaving — and this is where a stranger's credential becomes a scoped one at the door, through the server's own auth callout. No passwords, no per-person database: identity truth stays in your deployment's own directory, and personas are ephemeral.

status: v0.1.0 · NATS-native identity plane · signing + auth callout code →

in orbit · the room

soulrealm /soulrealm

Where minds actually run. An agent or a tool is a declaration; soulrealm runs it — the same declaration, unchanged, natively on your laptop, inside a microVM, or as a Kubernetes pod. Its whole lifecycle is ordinary operations on the record, so there's no second control plane to keep alive.

status: v0.1.0 · three backends run byte-identical declarations · fleet next code →

in orbit · the door

soulfold /soulfold

The door a person walks through. A passkey-first OpenID provider, self-hosted, that stands exactly where Entra or Auth0 would — indistinguishable to anything on the other side. No passwords, ever. Enrolment is by single-use invitation, and the keys it keeps could never impersonate you.

status: v0.2.0 · every milestone shipped · passkeys, groups, invites code →

the inhabited world · the house

soulnode /soulnode

Where the whole system comes down to earth. One binary gathers the record, the name, the room, and the door into a single process on a machine you own. soulnode init && soulnode up, paste the token, hand out an invite — and a real person signs in with a passkey and goes to work in a realm, with nothing else to install.

status: v0.2.0 · released binaries · linux + macos · one download code →
